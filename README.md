# マイツール（my-apps）

自分のための小さなツールをまとめた、モジュール式のPWAポータル。
ホーム画面に追加するのはこのポータル1つだけ。ツールはモジュールとして追加していく。

もともと Muse のスペースで作っていたツールを「正本は自分のGitHubに置く」方針で移植したもの。
コードもデータ形式もプレーンなファイルなので、特定のサービスにロックインされない。

## モジュール

| モジュール | 場所 | データの持ち方 | 内容 |
|---|---|---|---|
| ワークアウトログ | `workout/` | 端末内のみ（Android アプリ版あり → `android/`）＋任意でObsidianへ転記 | 自宅筋トレの記録。A/B/Cローテーション＋背中・脚・フットケア、進行ルール、脚の疲労感の記録。ホームの「隙間トレ」で体の部位マップ→種目の絵を選んでメニュー外の数セットを記録（1日1件にまとめ、順番・次回目標・週の回数には入れない）。記録画面の「途中で終わった」で順番と目標を進めずに保存 |
| 立替精算 | `reimburse/` | 接続先のGAS | 妻が立て替えた分の未精算と送金額。送金したら精算済みにする。明細はタップするとメモ・精算対象の切り替え・レシート画像が開ける。バックエンドは [tmhys/gas](https://github.com/tmhys/gas) の `receipt-reimbursement` |
| 買い物メモ | `shopping/` | 接続先のGAS（見送りの控えだけ端末内） | LINE で来た「買っといて」と欲しいもの。発注待ち／未確認／欲しいもの／発注済／見送りのタブ。発注済には発注日・到着予定・注文番号。**定期便はヘッダーの「定期便」から開く別ページ**で、Amazon のメールから作った一覧を見るだけ（買い物の依頼とは切り離してある）。バックエンドは [tmhys/gas](https://github.com/tmhys/gas) の `household-ordering` |

### 技術士 勉強（`gijutsushi/`）と Obsidian・習慣グリッドの連携

キーワード学習のレッスン（復習含む）を1回終える、または論文骨子を1本保存すると、
`gijutsushi/habit.js` が habit-relay に `action:"gijutsushi"` で記録を送る。
受け側（github_obsidian の `gijutsushi-log.yml`）が骨子を `10_Gijutsushi/骨子/` に1本1ノート、
レッスンなら `10_Gijutsushi/キーワード習熟.md` を作り直し、`05_Stream` に1行、
習慣「📘 技術士勉強」も同じ workflow で立てる（アプリから習慣を別に送らない）。

- 中継の URL・合言葉は habit-pwa と同じものを読む。my-apps と habit-pwa は同じ `https://tmhys.github.io`
  なので localStorage を共有している（ここでは保存しない）
- 送れなかった記録は `gijutsushi:outbox` に溜め、次にどの画面を開いたときにも送り直す。
  同じ id（骨子を編集して保存し直したもの）は Obsidian 側で上書きされる
- 中継役が古い版（`gijutsushi` を知らない）ときは、習慣だけを1日1回送り、記録は溜めておく。
  古い版かどうかは1日1回見直すので、中継役を更新すれば翌日以降に溜まった分が送られる
- アプリで骨子を消しても Obsidian 側のノートは消えない

**バックアップ**: 記録は端末の localStorage にしかないので、技術士ホームの「💾 まとめてバックアップ」で
キーワード学習と論文骨子を1つの JSON にまとめ、共有メニュー（Obsidian・Google ドライブ等）に渡す
（`gijutsushi/backup.js`）。7日以上あいて中身が変わっていれば、ホームの帯と各画面のトースト（1日1回）で催促する。
復元はホームの「復元」から（各モジュールが書き出した古い形式も読める）。
（Obsidian へは上の連携で自動で残るので、こちらは端末の移行・念のための控え）

**II-1（専門知識）**: 過去問の原文は持っていないので、キーワード学習のカードのうち出題区分に II-1 を含む
31語から「練習問題」を作る（画面に「過去問ではありません」と明記）。定義・原理／特徴／留意点／適用例の
4欄で、合計500〜700字・専門用語の数などを自動チェックする。
回答例は `gijutsushi/ronbun/ii1-answers.js`（答案用紙1枚・600字程度の文章。カード id がキー）で、その下にカードの要点を付ける。

**ハート**: レッスンだけに使う。復習はハートが0でもでき、間違えても減らない。

## 別アプリ（ポータルからリンクするだけ）

ホーム画面に置くのはこのポータル1つで済むように、外にある自分のアプリへのリンクも
トップに並べている。コードは各リポジトリのままで、ここでは何も持たない。

| アプリ | リポジトリ | リンク先の持ち方 |
|---|---|---|
| 習慣グリッド | [tmhys/habit-pwa](https://github.com/tmhys/habit-pwa) | `index.html` に直書き（ウェブ版） |
| らくな家計簿 | [tmhys/kakeibo-pwa](https://github.com/tmhys/kakeibo-pwa) | Android では **`kakeibo://`**（`portal.js`）、それ以外はウェブ版 |
| Claude Inbox | [tmhys/my_apps](https://github.com/tmhys/my_apps) の `apps/claude-inbox` | **端末の localStorage**（`portal.js`） |

前の2つは GitHub Pages のプロジェクトページ（`https://tmhys.github.io/<repo>/`）で、
もともと公開されているので直書きしている。公開先を変えたらルートの `index.html` を直す。

**らくな家計簿は Android アプリ（WebView）として入れてある。**
`kakeibo-pwa` の `android/` は TWA ではなく素の WebView アプリで、`AndroidManifest` に
https を受け取る intent-filter が無い。そのため https のリンクではアプリが起動せず
Chrome が開いてしまう。Android のときだけ `portal.js` が
`intent://open#Intent;scheme=kakeibo;package=com.tmhys.kakeibo;…;end` に差し替える。

**`MAIN` / `LAUNCHER` を指す `intent://` では起動しなかった。** Chrome は `intent://`
を発射するとき `BROWSABLE` カテゴリを必ず足し、Android は付いた全カテゴリを宣言して
いるアクティビティしか起動しないため。アプリ側に `VIEW` + `DEFAULT` + `BROWSABLE` で
`kakeibo://` を受ける intent-filter を足してある（`kakeibo-pwa` の `android/README.md`）。
**受け口のある APK（2026-11 以降のビルド）が要る。**

アプリが入っていない端末や古い APK は `browser_fallback_url` でウェブ版に落ち、
PC・iOS では差し替えずウェブ版のままにする。

**Claude Inbox だけ扱いが違う。** 本体は Cloudflare Workers で、ワーカーのホスト名は
どこにも公開していない。ここは公開リポジトリなので書かず、端末ごとにカードの
「設定する」から URL を入れる（`portal.js` が `portal:inboxUrl` に保存する）。
未設定の端末ではカードが「設定する」の表示になり、押しても開かない。

合言葉（`APP_TOKEN`）は Claude Inbox の画面側で入れるので、ここには保存しない。
`#t=...` 付きのURLを貼られても、保存時にハッシュを落とす。
`href` には `https:` のURLしか入れない（`javascript:` を弾くため）。

## モジュールの共通ルール

- **戻る操作は `nav.js` に任せる**。画面（タブ・クイズ・設定など）を切り替える関数を
  `show = MyNav.views('既定の画面のid', show)` で包むと、既定以外の画面で戻る操作をしたとき
  既定の画面に戻る（モジュールごと抜けない）。タブを渡り歩いても履歴は1つしか積まない。
  入力中の画面は `canLeave` で確かめてから戻す（ワークアウトログの記録入力）。
  上の階層へのリンクには `class="back"` を付ける。直前のページがその階層なら履歴を戻り、
  違えば履歴を置き換えるので、リンクで戻ったあとに戻る操作で元の画面に入り直さない
- **データの持ち方をモジュールごとに宣言する**（上の表）。混ぜない
  - 端末内だけのモジュール（ワークアウトログ）は、このリポジトリにもサーバーにも送らない。
    例外は本人が設定画面で宛先を入れたときだけ（ワークアウトログ→Obsidian）。
    宛先と合言葉は端末の `localStorage` にだけ置き、JSONの書き出しにも混ぜない
  - サーバーを使うモジュール（立替精算）は、**接続先を設定画面で入れる方式にする**。
    URLや合言葉をこのリポジトリに書かない。公開リポジトリなので置けば漏れる
- 端末内だけのモジュールは、設定画面から **JSONで書き出し／読み込み** ができること
  （バックアップと移行のため）。サーバー側が正本のモジュールは不要
- `localStorage` のキーは**モジュールごとの接頭辞**を付ける
  （`workoutLogPwa.`、`reimburse:`、`shopping:` など）。同じオリジンに別アプリが同居しているため
- 通知・リマインダーは付けない。必要ならバックエンド側（GAS）から送る

## 新しいツールの追加方法

1. リポジトリ直下にフォルダを作り、`index.html` 等を置く
2. ルートの `index.html` にカードを追加する
3. ルートの `sw.js` のキャッシュ対象にモジュールのファイルを追加し、`CACHE` の版を上げる
   （**版を上げ忘れると古いファイルが端末に残る**）
4. 上のモジュール表に「データの持ち方」を書く
5. 単体でホーム画面に置けるようにするなら：モジュールに `manifest.webmanifest`（`scope`/`start_url` は `./`）、
   `icons/<名前>-192.png`・`-512.png`、ページ末尾に `<script src="../install.js">`、
   ルートの `manifest.webmanifest` の `shortcuts` とランチャーのシート（`.pin-list`）に追加する
6. ランチャーに状況を出すなら：モジュール側で localStorage に要約を置き、`launcher.js` で読む

## ランチャー（`index.html` / `launcher.js`）

ダーク配色。**押すものは画面の下半分**（親指が届く位置）に集め、上は見るだけの情報にしている。

- カードの小さな状況と「次にやること」は、各ツールが端末に残した記録から作る（サーバーには聞かない）。
  ワークアウトは `workoutLogPwa.summary`、技術士は `pakuringo:state`、買い物メモ・立替精算は
  それぞれの `cache`（最後に開いたときの内容）。ワークアウトの Android アプリ版の記録は
  ブラウザから見えないので、習慣グリッドのスナップショット（`habit-pwa/data/habits.json`）の
  「💪 筋トレ」で今週やった日数を補う（id が不明なので id 候補か名前の「筋トレ／💪」で探す。
  反映は数分遅れ、結果は `portal:habitWorkout` に控える）。次のメニュー名はブラウザ版の要約にしか無い
- 「次にやること」は 筋トレ（今週の目標未達・今日未実施）→ 技術士（今日30XP未満）→ 発注待ち → 未精算 の順で最初に当てはまったもの
- **ホーム画面に置く**：①マイツールのアイコン長押しでツールのショートカットが出る（manifest の `shortcuts`。
  Android ではホーム画面へドラッグできる）②立替精算・買い物メモ・技術士勉強は自分の manifest を持つので、
  ランチャーのシートから `?install=1` で開くと `install.js` がインストールの案内を出す

## Android アプリ版（`android/`）

ワークアウトログだけ、WebView の Android アプリにしてある（`kakeibo-pwa` と同じ作り）。
中身は GitHub Pages の `workout/` をそのまま表示するので、**画面を直すときに
APK を作り直す必要はない**。APK を作り直すのは `android/` を変えたときだけ。

**記録はブラウザ（PWA）とアプリで別の場所に入る。** WebView の localStorage は
ブラウザのものと共有されない。移すときは、ブラウザ側で「JSONで書き出す」→
アプリ側で「JSONを読み込む」。どちらか一方に寄せること。

JSON の書き出しは、アプリの中では `window.WorkoutApp.saveFile` に渡す
（WebView では `a[download]` が効かないため）。詳しくは `android/README.md`。

## Service Worker について

**ネットワーク優先**。取れたものを控えに回し、圏外のときだけ控えを出す。
以前はキャッシュ優先だったため、更新を公開しても端末に届かなかった
（`kakeibo-pwa` は同じ理由で Service Worker を撤去している）。
さらに GitHub Pages の10分キャッシュで「HTML は新しく JS は古い」組み合わせが起きたため、
Service Worker は `cache: 'no-cache'` で取りに行き、`workout/index.html` は `app.js?v=N` のように版を付けて読む
（**workout を直したら `?v=` も上げる**）。

自分のオリジン以外は素通しする。立替精算モジュールは GAS に `?month=...` を付けて
問い合わせるので、以前の `ignoreSearch: true` の照合だと別の月の応答を
取り違える恐れがあった。

### 買い物メモについて

画面の作りは `household-ordering` の発注リスト画面（`WebApp.gs`）に**合わせてある**。
タブも、カードに出す項目も、タブごとのボタンも同じ。どちらで操作しても同じことが
起きるようにするため、このモジュールに独自の操作を足さない。

LINE からの取り込み・Gemini での構造化・二重発注の判定・相場調べはすべて gas 側にある。
POST の宛先には `api=app` を付ける。これが無いと gas 側は LINE の webhook として扱い、
別の合言葉で弾かれる。

## ワークアウトログのルール

- 器具は腹筋ローラー・プッシュアップバー・ゴムチューブ（＋自重）のみ。**脚の種目は入れない**（マラソンのタイムを落とさないため）
- 週3回・1回30分、A（胸＋三頭）→ B（腕＋肩）→ C（胸＋腹）のローテーション。曜日固定なし
- 進行ルール：全セット目標クリア＆RPE7以下で次回 **+1回**（秒数の種目は **+5秒**）。RPE9以上か回数未達なら据え置き
- 各セッションで「脚の疲労感（1〜5）」と「次のランの感覚」を記録する
- 設定画面で中継（[tmhys/gas](https://github.com/tmhys/gas) の `habit-relay`）のURLと合言葉を入れると、
  記録を保存したときに Obsidian の日記（`05_Stream`）へメニューと種目が1件として残る。
  習慣「💪 筋トレ」も受け側の workflow で同時に立つので、アプリから習慣を別に送ってはいけない
  （2回 dispatch すると commit がぶつかる）。空欄にすれば送信は止まる。
  送れなかったものは端末に溜め、次の起動時と設定画面の「未送信を送る」で送り直す。
  同じ記録を送り直しても、受け側が `id` で行を書き換えるので増えない
